## ② イベント説明欄（本文 — そのまま貼り付け）

毎月第2金曜日14時からはHCCJPの勉強会！9月は **Azure Arc を「実際の運用に入れる」** という話をします。

前回（第76回）は、オンプレのサーバーをその場で壊して、AIエージェントに直してもらいました。誰もそのサーバーにログインせず、VPNも踏み台もなしで、Azure 越しに調査から復旧まで通してしまう——**Arc で繋いでおけば、オンプレの面倒くささはかなり消える**、というところまではお見せできたと思います。

ただ、そこから「じゃあ本番でも使おう」に進むには、もうひとつ越える壁があります。

**「何かあったときに、どうなるんだろう？」**

### 気になること、ありませんか

- パッチを当てて壊れた。**スナップショットで巻き戻したら、Azure 側はどうなるの？**
- バックアップから復元した。**Arc の登録って、ちゃんと残ってるの？**
- Azure から配った拡張機能や構成が、巻き戻しで消えた。**自動で戻ってくるの？それとも人が入れ直すの？**
- ポータルには緑の「正常」が出ている。**それって実機の何を保証してるの？**
- そもそもエージェントが Azure と繋がらなくなったら、**現地に行かずに直せるの？**

——この「気になる」を放置したまま本番に入れると、いざというときに手が止まります。逆に言うと、**ここさえ潰しておけば、Arc は安心して運用に入れられる**はずです。

### なので、全部試してきました

今回は実機のラボ（Windows Server 2025 と Ubuntu 24.04）を使って、こういうことを片っ端から確かめた結果をお見せします。

**まず、Arc 経由で何ができるのかを棚卸しします。** パッチ管理、構成の監査と適用、拡張機能の配布、リモートでのコマンド実行、監視、セキュリティ、マネージドIDでの認証——「繋いだあとに何が手に入るのか」を、公式の分類に沿って整理し、実際に動かして確かめます。**Azure Update Manager** はその中心で、Azure のVMもオンプレのサーバーも同じ1画面で扱えます。**2026年5月に Windows Server 2025 の Hotpatch が Arc 接続マシンで追加費用ゼロになった**話も、あわせて扱います（再起動を減らせる話です）。

**そのうえで、「万が一」を実際に起こします。** スナップショットを取り、Azure 側から変更を進め、そして巻き戻す。バックアップから戻したときに Arc の状態がどうなるのかも整理します。**Azure 側の状態とローカルの状態がズレたとき（ドリフト）に何が起きて、何分で、どこまで自動で追いつくのか。** ログのタイムスタンプ付きで、そのままお見せします。

結果は、**きれいに自動で追いついたものと、追いついてこなかったものに分かれました。** WindowsとLinuxで挙動が違った部分もあります。

### 持ち帰っていただきたいのは「戻し方」です

大事なのは怖がることではなく、**「こうやれば元に戻せる」を手元に持っておくこと**です。

- スナップショットとバックアップは役割が違う。どちらを、どういうときに使うのか
- Arc の登録が壊れたときの復旧手順（実測で1〜2分でした）
- 復元・巻き戻しのあとに確認すべきことのチェックリスト
- 公式手順がカバーしている範囲と、その外側の見分け方

ここまで揃えば、**「じゃあ運用に Arc 入れてもいいね」「Update Manager も使っていこう」**と言えるようになる——そういう回にしたいと思っています。ぜひご参加ください！
