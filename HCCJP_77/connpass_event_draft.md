## ② イベント説明欄（本文 — そのまま貼り付け）

毎月第2金曜日14時からはHCCJPの勉強会！9月は **パッチ適用** をテーマにお届けします。

「すぐ当てろ」と言われて久しいのに、オンプレのサーバーにパッチを当てるのは、いまだに気が重い作業です。理由ははっきりしています。**当てて壊れたときに戻せる自信がないから。**

今回はそこを正面から扱います。

### 当てる側の話は、実はもう整っています

**Azure Update Manager** を使えば、Azure のVMもオンプレのサーバーも、**同じ1画面**でパッチの状態を見て、メンテナンス時間を決めて、まとめて当てられます。オンプレ側は Azure Arc で繋ぐだけ。VPNも踏み台も要りません（通信はアウトバウンド443のみ）。

さらに **2026年5月、Windows Server 2025 の Hotpatch が Azure Arc 接続マシンで追加費用ゼロになりました**。per-coreの課金メーターごと廃止です。**再起動を伴わずにパッチを当てる**という選択肢が、オンプレの資産にそのまま、しかもタダで降りてきています。ご存じでしたか？

一方で、オンプレを混ぜた瞬間に有料になる部分もあります。**課金の線引きがどこにあるのか**も、実際の数字でお見せします。

### 本題は「コケたときに戻せるのか」

パッチ適用の前にスナップショット（チェックポイント）を取る。当てて壊れたら戻す。——よくやる話ですが、**Azure Arc で管理しているサーバーでこれをやると、何が起きるのでしょう？**

考えてみてください。**Azure 側は先に進んでいます。** 拡張機能を配り、構成ポリシーを適用し、パッチを当てた記録を持っている。そこにローカルだけが過去に戻ってくる。

- Azure は、サーバーが巻き戻ったことに気づくのでしょうか？
- Azure が配った拡張機能は、自動で再適用されるのでしょうか？
- 「ドリフトしたら直す」設定にしてある構成ポリシーは、ちゃんと直してくれるのでしょうか？
- ポータルに出ている緑色は、そのとき実機の何を保証しているのでしょうか？

**公式ドキュメントを探しても、この答えは書いてありません。**

なので、**実機で測ってきました。** Windows Server 2025 と Ubuntu 24.04 をArcに繋ぎ、拡張機能と構成ポリシーを配り、スナップショットを取り、Azure側から変更を進め、そして巻き戻す。何分後に何が起きたかを、ログのタイムスタンプ付きで全部お見せします。

結果は——**きれいに追いついたものと、まったく追いついてこなかったものに、はっきり分かれました。** しかもWindowsとLinuxで挙動が違いました。どちらがどうだったかは、当日のお楽しみに。

### バックアップの話もします

チェックポイントはバックアップではありません。ホストごと failしたら一緒に消えますし、ランサムウェアには無力です。では Arc で管理しているVMを、いま何でどう守るのが正解なのか。**Microsoft公式の手順がどこまでカバーしていて、どこから先が「サポート外」になるのか**を整理します。「サポート外だから触らない」で止まっている論点を、「**サポート内で回る設計はこれ**」に変換してお持ち帰りいただきます。

「怖くて当てられない」を終わらせる回にしたいと思っています。ぜひご参加ください！
