## ② イベント説明欄（本文 — 下のエリアにそのまま貼り付け）

毎月第2金曜日14時からはHCCJPの勉強会！8月は **Azure Arc × AIエージェント** でお届けします。

第74回で「オンプレのマシンにNested Hyper-Vの検証環境をコードで建てる」お話をしました。今回はその**続き**です——**建てた環境をAzure Arcで繋いだら、そこから先はどこまでできるのか**。

Azure Arc でオンプレのサーバーを Azure に接続すると、そのサーバーは Azure リソースとして扱えるようになります。**インバウンドのポート開放なし、VPNなし、踏み台なし**（通信はアウトバウンド443のみ）。コマンド実行も、構成の強制も、パッチ適用も、SSH接続すら、Azure の Control Plane 経由で通ります。つまり**「サーバー室に行く」「VPNを繋ぐ」という前提そのものが消える**わけです。

そしてここが本題。Azure 側の入口が `az` コマンドに統一されているということは——**AIエージェントがそのまま運用の手を持てる**ということです。「あのサーバーのディスクが逼迫してる、原因を調べて直しておいて」と日本語で投げるだけで、AIがArc経由で対象を特定し、コマンドを流し、結果を読み、次の手を打つ。オンプレのWindowsもLinuxも、区別なく。

本セッションでは、これを**その場で実演**します。録画ではありません。**セッション冒頭でArc越しのパッチ処理を投げてイベント中ずっと裏で走らせ、最後にみんなで結果を確認**します。メインデモは「ディスクが逼迫したサーバーをAIに直させる」——使用率という**数字が目の前で下がる**ところまで見届けます。さらに、**チャットでいただいたお題をその場でAIに投げる**時間も用意しました。台本なしで「本当にできるのか」を試します。

あわせて、**AIにどこまでの権限を渡すべきか**——RBAC・監査ログ・操作の境界という、実運用で必ずぶつかる話も正面から扱います。

「オンプレは残る。でも運用する場所は変えられる」——AI時代のハイブリッドクラウド運用の姿を、一緒に見に行きましょう！

### 🎤 セッション内容

**1. AIに"オンプレの鍵"を渡してみた — Azure Arcで繋いだWindows/Linuxを、AIエージェントに運用させる**
胡田 昌彦（日本ビジネスシステムズ株式会社 / Microsoft MVP）

- 🎬 冒頭で仕込みを1本キックオフ — Arc越しに「全台のパッチ評価＆適用」を投げてから話し始めます（**イベントの間ずっと裏で走らせて、最後にみんなで結果を見ます**）
- なぜ今 Azure Arc なのか — オンプレは無くならない。無くせるのは「そこまで行く手間」のほう
- 繋ぐ仕組みのおさらい — Connected Machine agent / アウトバウンド443のみ / Arc Gateway
- Arc越しに"できること"の棚卸し — Run Command / Machine Configuration / 拡張機能 / SSH over Arc / Update Manager / Azure Monitor / Defender for Cloud
- ここにAIを繋ぐ — 入口が `az` に統一されている＝AIエージェントがそのまま運用の手を持てる
- ⭐ **メインデモ（ライブ）**：「このサーバー、ディスクが逼迫してる。原因を特定して空けて」をAIに丸投げ。調査→原因特定→対処→再確認まで、**使用率が実際に下がるところ**まで見届けます
- 🙋 **会場からのリクエスト**：チャットでいただいたお題を、その場でAIに投げます（台本なし！）
- 権限と怖さの話 — AIに何を許し、何を許さないか。RBACの切り方、監査ログ、壊さないための仕掛け
- 最後に答え合わせ — 冒頭に投げたパッチ処理は、90分でどこまで進んだのか

※ デモは実環境（第74回で建てたNested Hyper-Vラボ）を使用します。当日の状況により内容を調整する場合があります。
